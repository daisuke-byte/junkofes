# 中村韓国キッチン 会計アプリ

順煌祭（出店番号⑦）で出す参鶏湯の模擬店「中村韓国キッチン」で、販売スタッフが使う会計アプリです。
iPad のホーム画面に追加して使う PWA で、外部サーバーは使いません。通信がなくても動きます。

- 会計は「杯数 → 預かり → 確定」の3タップ。お釣りは画面でいちばん大きく、金種の内訳もいっしょに表示します
- 会計を確定するたびに、端末内の IndexedDB へすぐ保存します。保存に失敗したら確定しません
- 準備金からレジ締めまで、レジの中の現金を金種ごとに追いかけて照合します
- Slack へは、営業開始・毎正時・目標達成・売り切れ・営業終了のタイミングで自動投稿します。オフラインの間の通知は溜めておき、通信が戻ったら送ります
- レポートは A4・1枚の PDF と、CSV（BOM 付き UTF-8）で出力できます

### 実装上の判断

- **PDF**：レポートを Canvas に描き、それを JPEG 1枚として貼った A4 の PDF を自前で組み立てています。端末にある日本語フォントで描くので、フォントを埋め込まなくても文字化けしません。その代わり、PDF の中の文字は選択できません
- **PDF の共有**：iOS の共有シートはタップ直後でないと開けません。そのため「PDFを作成」と「PDFを共有（Slackへ）」の2つのボタンに分けています
- **お釣りの金種**：大きい硬貨から優先して出します。ただし、レジの理論残高にない硬貨は使いません（500円玉がなければ100円玉で出す計算になります）
- **締め後の再開**：設定画面の「締めを解除」から行います。理由の入力が必要で、解除した記録はセッションに残り、レポートにも載ります
- **在庫が0杯のとき**：「売り切れ」と表示して Slack にも通知します。仕込み数の見込み違いもあるので、会計自体は止めません

## 開発

```bash
npm install
npm run dev        # 開発サーバー
npm test           # 単体テスト（お釣り・理論残高・予測・送信キュー・CSV・PDF）
npm run build      # dist/ に出力（Service Worker も自動生成）
npm run preview    # ビルド結果を確認
```

構成：Vite + TypeScript（Vanilla）。実行時の依存ライブラリはありません。

## 公開（GitHub Pages）

1. GitHub のリポジトリで Settings → Pages → Source を「GitHub Actions」にする
2. `main` ブランチに push すると、`.github/workflows/deploy.yml` がテストとビルドを実行して公開する
3. 公開 URL は `https://<ユーザー名>.github.io/<リポジトリ名>/`。相対パスでビルドしているので、サブパスでもそのまま動きます

**Slack の Webhook URL は、リポジトリにもコードにも書かないでください。** URL はアプリの設定画面で入力し、その端末の中にだけ保存します。

## iPad での準備

1. Safari で公開 URL を開き、共有 →「ホーム画面に追加」を選ぶ
2. **以降は必ずホーム画面のアイコンから起動する**（Safari のタブとホーム画面のアプリはデータの保存場所が別です）
3. 機内モードにしてアイコンから起動できることを確認する
4. 設定 → Slack Webhook URL を入力し、「テスト送信」が Slack に届くか確認する
5. 設定 →「練習モード」で、通し練習（会計30件ほど → レジ締め → PDF 出力）をする
6. 練習が終わったら「練習データを消す」→「本番モード」に切り替える
7. iPad の 設定 → 画面表示と明るさ → 自動ロック を「なし」にする（Wake Lock が効かない場合の保険）

## 当日の流れ

1. 準備金を金種ごとに数えて入力し、「この金額で営業開始」を押す
2. 会計：杯数 → 預かり → 確定。確定すると杯数1・預かり未選択に戻ります
3. 毎正時の Slack 報告は、アプリを前面に出しているあいだだけ送られます（iPad の Safari は裏に回るとタイマーが止まるため）
4. 終了したら「営業終了」を押し、2人で金種ごとに数えて入力して「締めを確定」を押す
5. レポートで「PDFを作成」→「PDFを共有（Slackへ）」を押し、CSV もバックアップしておく
